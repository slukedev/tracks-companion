# First run, accounts and devices

## The setup token

A new server has no accounts. Until the first admin exists it serves only the setup page, the
health checks, `/api/v1/ping` and `/api/v1/capabilities`, so nobody else on your network can
claim it.

On that first start it prints a banner to its log:

```
Trackside needs an admin account. Open http://192.168.1.20:4747/setup and enter this setup token:
  7KQ2-M9XD-...-P4TA
The token is also in /data/setup-token. It stops working once the admin exists.
```

Where to find it:

| Install | Command |
|---|---|
| Docker Compose | `docker compose logs trackside` |
| Docker | `docker logs trackside` |
| systemd | `sudo journalctl -u trackside` |
| Homebrew | `cat "$(brew --prefix)/var/trackside/setup-token"` |
| Anything | the file `setup-token` in the data folder |

Open `/setup`, enter the token, and choose a username and password (8 characters or more).
That account is an admin. The token file is deleted and the token stops working.

If the token is lost before anyone used it, make a new one on the host:

```sh
docker compose exec trackside trackside admin create-setup-token
# or, without Docker:
trackside admin create-setup-token
```

### Creating the admin without the browser

For automated installs, set both of these before the first start and the server creates the
admin itself:

```yaml
environment:
  TRACKSIDE_ADMIN_USERNAME: luke
  TRACKSIDE_ADMIN_PASSWORD_FILE: /run/secrets/trackside_admin_password
```

`TRACKSIDE_ADMIN_PASSWORD` works too, but a file keeps the password out of `docker inspect`.
Both are ignored once any admin exists.

## Your music

If `/music` (Docker) or `TRACKSIDE_MUSIC_DIR` has files in it on the first start, it becomes a
library called "Music" and the first scan starts straight away. Otherwise add libraries in the
dashboard under **Libraries**. [libraries.md](libraries.md) covers more than one library,
NAS folders and permissions.

## People

Admins add people with an invite: **Invites**, then **New Invite** (or **Invite Someone** on
the Users page). Choose a role, what they may do (downloads, uploads, requests, Subsonic app
passwords, a bitrate limit) and which libraries they see, and send them the link or the QR
code. It works once and expires after 7 days unless you choose otherwise. They choose their own
username and password, and the account gets exactly what the invite said.

| Role | Can |
|---|---|
| admin | everything, every library, the dashboard's admin pages |
| member | their own listens, favourites and playlists, in the libraries they were given; downloads, uploads, requests and Subsonic app passwords only if allowed |

The last admin can't be demoted, disabled or deleted, so a server always has one.

## Devices

Every phone, Mac or app that connects gets its own key, listed under **Devices and Keys**
with when and where it was last used. Revoking one signs that device out at once and doesn't
touch the others. Keys can't reach admin pages: those need a browser session, so a lost phone
can't be used to take over the server.

Ways to connect Tracks (Settings, Play, Servers, **Connect a Server…**):

- **QR code, on iPhone.** In the dashboard, **My Account**, then **Show Code** under Pair a
  Device. In Tracks, tap **Scan Pairing Code** and scan it. The code carries every address the
  server knows, so Tracks can pick the fastest at home and away.
- **Code.** The same box shows an 8-character code such as `Q7RM-4X2K`. In Tracks, enter the
  server's address (or pick it under On Your Network), choose **Code** and type it. This is the
  way to pair a Mac without a password.
- **Approval.** Enter the address, choose **Approval** and then **Pair**. Tracks shows a
  6-digit code; in the dashboard, enter it under "Code from the app" on **My Account** (or
  **Approve a Code** on **Devices and Keys**). Tracks finishes by itself once it's approved.
- **Password.** Enter the address, choose **Password**, and sign in with your username and
  password. Tracks keeps only the device key it gets back.

Pairing codes last 10 minutes and stop after five wrong tries.

Before Tracks sends a key, a code or a password to an address, the address has to prove it is
your server. Over plain `http://` Tracks only sends them to addresses on your own network (a
LAN address, a `.local` name or a Tailscale address); anything farther away needs HTTPS.

## Other apps

Under **My Account**, App Keys, **New Key**:

- a **key** for apps that support OpenSubsonic API keys (most current ones). Prefer these.
- an **app password** for older Subsonic apps that send a username and password. An admin has
  to allow them for the account first. Each is generated by the server, shown once with the
  username to type alongside it, can be revoked on its own, and is never your login password.

Making a key, like other sensitive changes in the dashboard, asks for your password again if
you signed in more than 10 minutes ago.

## Locked out

On the host, while the server runs:

```sh
trackside admin list-users
trackside admin reset-password <username>   # prints a temporary password, ends their sessions
trackside admin set-role <username> admin    # makes someone an admin again
```

In Docker, prefix each with `docker compose exec trackside`. A member who forgets their
password can get a reset link from an admin: **Users**, the person, **Make Link**.
